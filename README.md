## New to Packet Tracer? Read this first

1. **Install / open**: open Cisco Packet Tracer and log in (Cisco NetAcad account or guest).
2. **Open a lab**: download the `.pkt` from the table above → in Packet Tracer **File → Open** → choose the file. (Or double-click the file.)
   If asked to save the current file, choose **No**.
3. **The screen**: the big white area is the *logical workspace* with the devices. The bottom-left has the device library
   (not needed, the labs are already built). The bottom-right has **Realtime** / **Simulation** mode tabs.
4. **Cable lights**: each cable end has a dot. **Green** = working, **orange** = switch port still starting (wait ~30 s),
   **red** = down/shut. Press **Fast Forward Time** (bottom-left clock area) to skip waiting.
5. **Open a PC's command prompt**: click the PC → **Desktop** tab → **Command Prompt**. Type commands like `ping 192.168.1.1`.
   Other useful Desktop apps: **IP Configuration** (set static IP or DHCP) and **Web Browser**.
6. **Open a router/switch CLI**: click the device → **CLI** tab → press **Enter** → you see `R1>`.
   - `enable` → `R1#` (show commands work here)
   - `configure terminal` → `R1(config)#` (change settings)
   - `exit` goes back one level, `end` goes back to `R1#`.
   - Press **Tab** to auto-complete a command, `?` to list options. Close the device window with the X when done.
7. **Simulation mode** (to *see* packets): click **Simulation** → **Add Simple PDU** (closed envelope on the right toolbar)
   → click the source device, then the destination → press **Play** (▶) in the Simulation panel. Click **Realtime** to go back.
8. **Save your work**: **File → Save As**. Saving with a newer Packet Tracer version may not open in an older one.
9. **Passwords used in these labs**: console/vty `cisco`, enable secret `class` (only Lab 3 SW1 and Lab 5 MyRouter/MySwitch ask for them).
10. **A ping fails the first time?** The first 1–2 pings often time out while ARP runs. Ping again. If it still fails, check that the cable dots are green.

## Program 1: Introduction to Packet Tracer & networking devices

**File:** [Lab01_Intro_Devices.pkt](https://github.com/abhiyansh-coding/cn-lab-packet-tracer/raw/main/labs/Lab01_Intro_Devices.pkt)

**Aim:** Introduction to Packet Tracer and networking device components (routers, switches, end devices, hubs, cables).

**Also asked as:** Introduction to Cisco Packet Tracer; Study of networking devices: router, switch, hub, PC, server; Study of network cables and connectors (straight-through, crossover); Difference between router, switch and hub; Build a simple network in Packet Tracer

**Topology:** Router (2911), switch (2960), hub, PCs and a server connected with straight-through copper cables. LAN 1 (switch) = 192.168.1.0/24, LAN 2 (hub) = 192.168.2.0/24.

### Steps: open, run and verify

1. Open **Lab01_Intro_Devices.pkt** in Packet Tracer (File → Open).
2. Wait for every dot on the cables to turn **green** (up to ~30 s on switches; press **Fast Forward Time** at the bottom-left to speed it up). Dots on the hub links stay green right away; the switch ports go orange → green.
3. Hover over each device to see its model and IP. Click **R1** → **Physical** tab to see the router hardware and its ports.
4. Note the cable types: solid black = straight-through (used everywhere here).
5. Click **PC0** → **Desktop** tab → **Command Prompt** → type `ping 192.168.1.11` → expect `Reply from 192.168.1.11` (same LAN, via the switch).
6. Still on PC0: `ping 192.168.2.10` → expect replies (different LAN, goes through R1). The first reply may time out (ARP), which is normal.
7. Click **PC0** → **Desktop** → **Web Browser** → type `192.168.1.100` → **Go** → the server's default web page appears.
8. Bonus: click **Simulation** (bottom-right, next to Realtime), press **Add Simple PDU** (the closed envelope icon at the right), click PC2 then PC3, press **Play**. Watch the hub copy the packet to *every* PC. Repeat between PC0 and PC1: the switch sends it only to PC1.

## Program 2: Network utility commands

**File:** [Lab02_Network_Utilities.pkt](https://github.com/abhiyansh-coding/cn-lab-packet-tracer/raw/main/labs/Lab02_Network_Utilities.pkt)

**Aim:** Use network utility commands such as PING, NETSTAT, IPCONFIG, ARP, TRACERT and NSLOOKUP.

**Also asked as:** Network utility / diagnostic commands; Use of ping, tracert/traceroute, ipconfig, arp, nslookup, netstat; Check connectivity between hosts; DNS name resolution / configure a DNS server; Display the ARP table / IP configuration

**Topology:** Two LANs joined by R1, with a DNS server (192.168.1.100) and a web server (192.168.2.100, name `www.cnlab.com`). Run the commands from any PC > Desktop > Command Prompt.

### Steps: open, run and verify

1. Open **Lab02_Network_Utilities.pkt** in Packet Tracer (File → Open).
2. Wait for every dot on the cables to turn **green** (up to ~30 s on switches; press **Fast Forward Time** at the bottom-left to speed it up).
3. Click **PC0** → **Desktop** tab → **Command Prompt**. Run each command below and note the output:
4. `ipconfig` → shows IP 192.168.1.10, mask 255.255.255.0, gateway 192.168.1.1. `ipconfig /all` also shows the MAC address and DNS server 192.168.1.100.
5. `ping 192.168.2.10` → 4 replies with time and TTL. (`ping -n 10 192.168.2.10` sends 10.)
6. `tracert 192.168.2.100` → hop 1 = 192.168.1.1 (R1), hop 2 = 192.168.2.100 (destination).
7. `arp -a` → lists IP → MAC entries learned during the pings (e.g. 192.168.1.1 with R1's MAC).
8. `nslookup www.cnlab.com` → `Server: 192.168.1.100`, `Address: 192.168.2.100`.
9. `ping www.cnlab.com` → the name resolves to 192.168.2.100 and replies come back.
10. Click **PC0** → **Desktop** → **Web Browser** → `www.cnlab.com` → **Go** → page loads. Then in Command Prompt run `netstat` to see the connection.
11. To see the DNS records: click **DNS-Server** → **Services** tab → **DNS** (records `www.cnlab.com` and `dns.cnlab.com`).

## Program 3: Star topology using hub and switch

**File:** [Lab03_Star_Hub_Switch.pkt](https://github.com/abhiyansh-coding/cn-lab-packet-tracer/raw/main/labs/Lab03_Star_Hub_Switch.pkt)

**Aim:** Star topology using a hub and a switch, IP configuration of end devices, show command, copy command, password setting, hostname setting.

**Also asked as:** Star topology; Hub vs switch; Connect PCs using a hub / using a switch; Assign IP addresses to PCs; Set hostname and passwords on a switch; Save configuration (copy running-config startup-config); Basic show commands on a switch; Collision domain vs broadcast domain

**Topology:** Star 1: 3 PCs on a hub (192.168.1.0/24). Star 2: 3 PCs on switch SW1 (192.168.2.0/24). SW1 has hostname, console/vty password `cisco`, enable secret `class`, banner, and the config is saved (`copy running-config startup-config`).

### Steps: open, run and verify

1. Open **Lab03_Star_Hub_Switch.pkt** in Packet Tracer (File → Open).
2. Wait for every dot on the cables to turn **green** (up to ~30 s on switches; press **Fast Forward Time** at the bottom-left to speed it up).
3. Click **PC0** → **Desktop** tab → **Command Prompt** → `ping 192.168.1.12` → replies (hub star).
4. Click **PC3** → **Desktop** tab → **Command Prompt** → `ping 192.168.2.12` → replies (switch star).
5. Hub vs switch: switch to **Simulation** mode (bottom-right), click **Add Simple PDU** (envelope icon on the right toolbar), click PC0 then PC2, press **Play** → the hub floods the packet to PC1 too. Do the same from PC3 to PC5 → the switch delivers only to PC5 (after the first ARP). Switch back to **Realtime**.

## Program 4: DHCP on a router

## Program 6: Static routing

**File:** [Lab06_Static_Routing.pkt](https://github.com/abhiyansh-coding/cn-lab-packet-tracer/raw/main/labs/Lab06_Static_Routing.pkt)

**Aim:** Configure static routing on routers so packets reach the correct destination network through predefined paths.

**Also asked as:** Static routing; Configure static routes between two routers; ip route command / next hop; Connect two networks with routers; Inter-network communication using routers

**Topology:** R1 (LAN 192.168.1.0/24) and R2 (LAN 192.168.2.0/24) linked by 10.0.0.0/30, with a static route on each.

### Steps: open, run and verify

1. Open **Lab06_Static_Routing.pkt** in Packet Tracer (File → Open).
2. Wait for every dot on the cables to turn **green** (up to ~30 s on switches; press **Fast Forward Time** at the bottom-left to speed it up).
3. Click **PC0** → **Desktop** tab → **Command Prompt** → `ping 192.168.2.10` → replies (the first may time out).
